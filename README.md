# Chaimel Enjambre — Portfolio

Nuxt 4 + Vue 3 + TypeScript + SCSS (Node 22.22+ or 24.15+). Static: every page renders from typed
copy in `app/data/`, and `npm run generate` prerenders the whole site for Netlify.

The structure and conventions follow `bpo/frontend`.

## Run

```bash
npm install
npm run dev        # http://localhost:3000
npm run generate   # static build into .output/public (what Netlify runs)
npm test           # data checks: images exist, icons exist, every project lists its stack
npm run typecheck  # vue-tsc over every .vue and .ts file
```

`predev` / `prebuild` / `pregenerate` run `app/icons/build-icons.js`, which turns the SVGs in
`app/icons/src/` into `public/icons/sprite.svg` and the typed icon list in `app/data/ui/icons.ts`.
Add an SVG there to get a new `MIcon` name (see `app/icons/README.md`).

## Structure

```text
app/
  assets/scss/          base/ partials (fonts, colors, reset, preset, typography, layout) + _component.scss (every m-* style)
  components/
    base/               M* primitives — auto-imported (MButton, MHeading, MText, MIcon, MTag, MBadge, MEyebrow, MBreadcrumbs, MModal)
    core/               composed UI shared across features: project/ (MBrowserShot, MPhoneShot), section/ (MSectionHead)
    layout/             Header, Footer, Logo, ScrollProgress
    features/<page>/    page sections; each Index.vue composes its sections
      home/             banner/ (Index, Rotator, Showcase) · Featured · work/ (Index + Card = full-width stacking cards, Viewer = project preview) · About · Experience · Skills · Contact
      project/          the case study: Banner · Overview · Flow · Highlights · Screens · Cta
  composables/app/      useCanonical, useModal (open/close dialogs by name), useActiveSection (header scrollspy), useSectionScroll (in-page links)
  data/features/        site.ts (name, contact, nav) · home.ts (hero, story, roles, education, skills) · projects.ts
  data/ui/icons.ts      generated by the icon build
  icons/                build-icons.js + src/light/*.svg
  layouts/              default
  pages/                index · projects/[slug] (pick the feature, set meta, pass props)
  plugins/reveal.ts     v-reveal: fade content up as it scrolls into view
  types/                base/ · app/ · features/
  utils/                format (host labels, role dates) · errors (notFound)
public/
  images/projects/      WebP screenshots (see Images)
  icons/sprite.svg      generated
tests/                  node --test checks for the data
```

## Routes

| Route | What |
| --- | --- |
| `/` | Hero, featured project, more work (full-width stacking cards + preview window), about, experience, skills, contact |
| `/projects/[slug]` | Case study — only projects with a `case_study` get a page (today: `duelo-battleground`) |

## Editing content

Everything on the page comes from `app/data/features/`:

- **A new project** — add it to `projects.ts` with its `summary`, `languages`, `stack`, `category`,
  an `accent` (the client's brand color as hex — it tints the project's card and preview), and a
  full-page screenshot. The work grid shows websites in the order listed. Set `status: 'offline'` if the client's site goes down: the card keeps the
  screenshot but drops the link. Add a `case_study` to give it its own page.
- **Your story, roles, education, skills** — `home.ts`. Banner counts (projects, roles) are computed
  from these lists.
- **Name, email, phone, résumé path, nav** — `site.ts`.

### Images

Screenshots live in `public/images/projects/` as WebP:

- Website cards use a **full-page** capture, 800px wide (the card scrolls it on hover).
- The featured project also has a 1600×1000 desktop `cover`, a 600px-wide `phone` capture, and the
  case-study screens.

Record each image's real `width` and `height` in `projects.ts`: they reserve the layout box and
set how long the hover scroll takes. `npm test` fails if a listed image is missing.

## Deployment & SEO

Netlify runs `npm run generate` and publishes `dist` (see `netlify.toml`).

Absolute-URL SEO tags (`canonical`, `og:url`, `og:image`, `twitter:image`) need the real production
origin, so they are **only emitted when it is configured** — the app never ships a guessed domain:

```bash
NUXT_PUBLIC_SITE_URL=https://your-domain.example npm run generate
```

On Netlify, set `NUXT_PUBLIC_SITE_URL` under Site settings → Environment variables.
The social card is `public/og-image.png` (1200×630); its source is `public/og-image.svg`.

`app/app.vue` also emits JSON-LD `Person` structured data, and each case study sets its own title,
description, and canonical.

## Conventions

Same as `bpo/frontend`: BEM blocks named after the component file, scoped SCSS in every section,
tokens only (no hex or rgba in components — add a token to `base/_colors.scss` instead; a
project's `accent` is content, so it arrives from the data as a CSS variable),
`block > .wrapper > .block__con` section markup, snake_case locals, typed props with `withDefaults`.
Headings are `MHeading` and paragraphs are `MText`, sized from the type scale in
`base/_typography.scss`. Types live in `app/types/`, never in data or component files. Feature and
core components are imported explicitly; only `components/base/` is auto-imported.
